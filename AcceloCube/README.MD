AcceloCubePro uses a simple MVVM setup: SwiftUI drives the UI, SceneKit renders the cube and trail, and MotionVM wraps CMMotionManager to read fused DeviceMotion in the xArbitraryZVertical frame. Orientation is handled as quaternions; on first start we capture a neutral pose and apply its inverse so what you see is calibrated to “forward.” Smoothing uses an alpha of 0.20, which keeps motion responsive while knocking down jitter; orientation blending uses slerp with the same factor so rotations feel steady without feeling laggy. Damping is 0.02 per tick to bleed off integrated velocity and curb drift without making the cube feel sticky. Drift is further controlled by three things: optional high-pass on user acceleration to remove slow bias, a speed cap at 5 m/s so noise spikes don’t explode, and a position clamp to ±2 m so the cube stays in bounds. You can re-center translation at any time without losing orientation, or run Calibrate to make the current attitude the new neutral. Sample rate is user-selectable (sliders and a segmented control) and hot-applied; when logging is on, we restart the stream so CSV rows include the latest config. The SceneKit bridge rebuilds a lightweight line geometry for the trail with per-vertex fade and throttles updates to about 30 Hz for stability.
